# 多表手动同步设计说明

## 目标

系统提供一个固定配置的 Web 操作页面。业务人员点击“同步”并确认后，把 10 张分表中的三个时间节点同步到一张固定总表。

系统没有后台定时执行能力，也没有机器人、消息回调、对话命令或主动通知能力。

## 执行流程

1. 用户在 Web 页面点击“同步”并确认。
2. 后端读取固定总表。
3. 后端依次读取全部分表。
4. 核心逻辑按货号聚合三个字段。
5. 系统识别重复货号、总表缺失货号和跨分表冲突。
6. 系统通过写入护栏校验后更新总表。
7. 运行摘要保存到本地 JSON 文件并显示在页面上。

## 页面和进度

首页只保留同步按钮、最近一次同步情况和配置规则入口。详细配置和规则默认隐藏在弹窗内。

最近一次同步情况从 `run.jobs` 提取失败分表名称和 `errorMessage`，并从 `run.conflicts` 读取冲突货号及相关分表。失败原因和冲突明细默认隐藏，仅在存在对应结果时提供弹窗入口。失败原因弹窗逐张显示分表名称和 DWS 返回的具体错误；每个冲突货号在冲突弹窗中占一行。

同步进度按“总表读取 + 每张分表读取 + 汇总 + 写入”计算。当前 10 张分表对应 13 个真实步骤。`GET /api/status` 在任务运行时返回 `progress`、`phase`、`completedSteps` 和 `totalSteps`。由于 DWS 单次表格读取和写入是同步调用，进度只能在步骤完成后更新，单个步骤内不会虚构进度。

## 字段规则

主键为 `货号`，同步字段为：

- 齐色主附图完成时间
- A+完成时间
- 视频完成时间

来源货号存在时，每个字段都按分表原值参与同步：

- 日期或普通文本：原样写入
- `/`：原样写入
- 空字符串：清空总表对应字段

来源货号在所有分表中都不存在时，不修改总表该行。

## 多分表冲突

同一货号可能出现在多张分表中：

- 三个字段完全一致时可以同步。
- 任一字段不同就标记为冲突并跳过整个货号。
- 空白与非空属于不同值，也会形成冲突。
- 冲突结果包含来源分表、行号和值，空白在页面上显示为“(空)”。

## 异常处理

- 连续的货号列和字段列按行分块合并读取，当前正式配置的 `B:E` 每个分块只发起一次请求；非连续列和常量字段继续使用兼容读取路径。
- DWS 返回 `HSFTimeOutException`、`stateServer.model.timeout`、`timeout before step apply` 等瞬时超时时，先重试当前分块；仍失败时自动缩小行分块后重试。
- 单张分表读取失败：其他分表继续处理，运行结果为部分错误。
- 所有分表读取失败：运行失败，不写入总表。
- 分表货号不在总表：记录失败，不自动新增行。
- 总表货号重复：记录失败，不写入该货号。
- 已有任务运行：新请求返回冲突，不重复启动。
- 写入目标与白名单不一致：写入护栏直接拦截。

## 模块职责

- `src/app.js`：Web 服务和手动接口
- `src/sync/sync-service.js`：一次手动任务的读取、聚合、写入和记录
- `src/sync/core.js`：纯数据匹配和差异计算
- `src/dingtalk/sheet-client.js`：DWS 表格读写及本地 CSV mock
- `src/config/sync-plans.json`：固定表格、字段和写入护栏配置
- `src/storage/run-repo.js`：最近运行记录
- `public/`：浏览器操作页面

## 非功能范围

当前版本不提供：

- 定时或后台自动同步
- 钉钉机器人和消息回调
- 用户自定义选择分表、总表或字段
- 自动新增总表货号
- Web 登录鉴权

因此部署时应把页面限制在可信内网或通过反向代理增加访问控制。

## 测试边界

自动化测试会验证：

- 本地 mock 端到端同步能够用空值清空目标字段
- 批量 CSV 写入载荷保留空字段
- 行范围更新载荷使用空文本单元格
- 单元格级回退写入显式发送空字符串
- 连续列合并读取能够保留空行和空单元格
- 状态服务超时会触发重试和行分块缩小
- 非连续列与常量字段仍使用兼容读取路径

这些测试能够确认程序发出的写入请求符合“空白覆盖”规则，但不能替代钉钉在线表格的真实写入验证。获得可安全修改的测试货号后，仍应补做一次线上验收。
